# Android language behavior

Guidance speech, framing, movement, uncertainty/recovery messages, keypad layout announcements and private PIN-help voices follow the language selected in Fingerpost settings (English, Hindi or Spanish). Changing that setting updates both guidance and PIN voice engines. Missing Hindi/Spanish voices use the specified English warning and English voice fallback. PIN digits remain in the private, active, ready, earphone-checked `PinMode.speak` path; only non-sensitive missing-voice warnings enter the shared speaker queue.

Settings labels/options, session states, action descriptions, permission errors and tutorial controls use Android resources in `values`, `values-hi` and `values-es`. They follow the Android system/app resource locale; the Fingerpost Language option controls guidance speech and does not change Android locale. Other system locales fall back to English. Debug-only tracking labels and numeric timing telemetry remain developer diagnostics.

Source regression tests cover localized movement, framing/recovery keys and keypad announcements. JVM tests, debug APK/test APK compilation and lint pass in the Day 6 continuation; see [coding evidence](evals/day6-coding-completion.md). Resource XML parsing, resource-name uniqueness/completeness and whitespace checks also pass. Font scaling, TalkBack, earphone route changes, installed/missing voices and native-language listen-through remain device acceptance work; no live results are claimed.


Day 6 continuation: basic-mode recognition uses only the Android on-device service on API31+, and older/missing services are unavailable safely. Basic-mode TTS also selects non-network voices; local English is the permitted missing-Hindi/Spanish fallback. With no local output voice it displays a localized instruction to install one rather than sending recognized labels to network TTS. Actual language packs, audibility and a native listen-through remain unverified. [Android on-device API reference](https://developer.android.com/reference/android/speech/SpeechRecognizer#createOnDeviceSpeechRecognizer(android.content.Context)).
